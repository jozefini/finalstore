# State Selectors

Selectors compute derived state. Think of them as the query language for your store.

`finalstore` offers two ways to select state: **inline selectors** for quick, component-specific queries, and **pre-defined selectors** for reusable, performant, and app-wide computations.

## Inline Selectors

Use an inline selector for simple, one-off state access directly within your components. Just pass a function to `store.use()` or `store.get()`.

```tsx
import { store } from './store';

function Profile() {
  // Select a single value
  const name = store.use((state) => state.user.name);

  // Select multiple values into a new object
  const { count, user } = store.use((state) => ({
    count: state.count,
    user: state.user
  }));

  return (
    <div>
      <p>Name: {name}</p>
      <p>Count: {count}</p>
    </div>
  );
}
```

This is great for co-locating simple state selection with the component that uses it.

## Pre-defined Selectors

Define selectors in your `createStore` config to create reusable, memoized functions for accessing derived state. This is the key to keeping your components clean, your logic centralized, and your application fast.

### The Power of Pre-defined Selectors

1.  **Type-Safe Composition:** By providing the `Selectors` type to `createStore`, you unlock the ability for selectors to safely call other selectors. This is a powerful pattern for building complex, derived state from smaller, reusable pieces.

    ```ts
    // store.ts
    import { createStore } from 'finalstore';

    // 1. Create store types
    type States = { ... }
    type Actions = { ... }
    type Selectors = {
      completedTodos: () => Todo[];
      pendingTodos: () => Todo[];
      stats: () => { completed: number; pending: number };
    };

    // 2. Pass types to createStore.
    // The `Selectors` type must be passed as the third generic argument.
    const store = createStore<States, Actions, Selectors>({
      states: {
        todos: []
      },
      selectors: ({ states, selectors }) => ({
        completedTodos: () => {
          return states.todos.filter((todo) => todo.completed);
        },
        pendingTodos: () => {
          return states.todos.filter((todo) => !todo.completed);
        },
        // ✅ This selector calls other selectors!
        stats: () => ({
          completed: selectors.completedTodos().length,
          pending: selectors.pendingTodos().length
        })
      })
    });
    ```

2.  **Automatic Memoization:** Pre-defined selectors are memoized out of the box. `finalstore` tracks which state they depend on and only recomputes them when that specific state changes. This prevents expensive calculations and unnecessary re-renders.

3.  **Keep Components Lean & Reusable:** Move complex logic out of your components and define it once. Then, reuse it anywhere—in any component (`store.use`) or outside of React (`store.get`).

    ```tsx
    // Instead of this complex logic in your component...
    const stats = store.use((state) => {
      const completed = state.todos.filter((t) => t.completed).length;
      const pending = state.todos.filter((t) => !t.completed).length;
      return { completed, pending };
    });

    // ...just call your clean, pre-defined selector:
    const stats = store.use.stats();
    ```
