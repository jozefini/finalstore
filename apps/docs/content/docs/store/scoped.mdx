# Scoped Stores

While global stores are great for app-wide state, sometimes you need state that is isolated to a specific component tree. `finalstore` provides `createScopedStore` for this exact purpose.

Scoped stores are perfect for:

- Reusable components that manage their own complex state (e.g., a multi-step form, an interactive widget).
- Feature-level state that doesn't need to be global.
- Preventing state from one component instance from interfering with another.

## Creating a Scoped Store

`createScopedStore` works just like `createStore`, but instead of a store instance, it returns a `Provider` component and a `useStore` hook.

```ts
// features/form/form-store.ts
import { createScopedStore } from 'finalstore';

// Define types just like you would for a global store
type States = {
  formData: { name: string; email: string };
  isSubmitting: boolean;
};
type Actions = {
  updateField: (field: string, value: string) => void;
  setSubmitting: (isSubmitting: boolean) => void;
};

// createScopedStore returns a Provider and a useStore hook
export const { Provider, useStore } = createScopedStore<States, Actions>({
  states: {
    formData: { name: '', email: '' },
    isSubmitting: false
  },
  actions: ({ states }) => ({
    updateField: (field, value) => {
      states.formData[field] = value;
    },
    setSubmitting: (isSubmitting) => {
      states.isSubmitting = isSubmitting;
    }
  })
});
```

## Using a Scoped Store

1.  **Wrap your component tree** with the `Provider`. This creates a new, isolated instance of the store for that tree.
2.  **Call the `useStore` hook** inside any child component to get access to that specific store instance.

```tsx
// features/form/form.tsx
import { Provider, useStore } from './form-store';

function Form() {
  const store = useStore(); // Accesses the store from the Provider
  const formData = store.use((state) => state.formData);
  const isSubmitting = store.use((state) => state.isSubmitting);

  const handleChange = (e) => {
    store.dispatch.updateField(e.target.name, e.target.value);
  };

  return (
    <form>
      <input name="name" value={formData.name} onChange={handleChange} />
      <input name="email" value={formData.email} onChange={handleChange} />
      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Submitting...' : 'Submit'}
      </button>
    </form>
  );
}

// Render multiple, independent instances of the form
export default function App() {
  return (
    <div>
      <h2>Contact Form</h2>
      <Provider>
        <Form />
      </Provider>

      <h2>Newsletter Signup</h2>
      <Provider>
        <Form />
      </Provider>
    </div>
  );
}
```

Each `<Provider>` creates a completely separate store instance. The state of the "Contact Form" will not affect the state of the "Newsletter Signup" form, even though they are the same component. The store is automatically created when the `Provider` mounts and destroyed when it unmounts, ensuring no memory leaks.
